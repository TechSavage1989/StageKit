# StageKit 0.1.0-betaNEXT

A frame-time release: StageKit's filters do less work every frame, so OBS's *Average time to render
frame* should come back down in a scene collection with many StageKit filters. Nothing you see
changes. Tested on Linux only. The Stream Deck plugin is unchanged.

## Changed

- **Less work every frame.** Filters that watch your scenes now look again when something in a scene
  changes (a source shown, hidden, added, removed, moved or resized), not many times a second
  whatever happens:
  - **Show in Scenes** with *Follow what is shown*.
  - **Link Visibility** with *Follow the first source*. A source shown while its leader is hidden is
    still hidden again straight away.
  - **Shadow, Glow & Outline**: checking how big its source is drawn, and *Keep it on screen*.
  - **Ambient Background**: finding the live capture to blend in.
  Each still takes a slow look now and then, in case something changed that OBS does not announce.
  On a test collection shaped like a large StageKit setup (18 scenes, 36 Fit to Space, 23 shadows),
  StageKit's own work each frame went down by 28 to 44 % depending on the scene: 42 % with the main
  layout scene on screen, 44 % with nothing on screen.
- **The OBS log says more about frame time.** The `timing` lines give their times to the microsecond,
  and one more line gives all of StageKit's work a frame together when it is noticeable:
  `timing, last 30 s: StageKit ticks 0.123 ms a frame (fit_item 0.081, ...)`. Send the log if OBS's
  frame time goes up.

## Fixed

- **A source with a shadow and a bounding box no longer shifts by a pixel and back three times a
  second.** The shadow's room depends on how big the source is drawn, and in a bounding box how big
  it is drawn depends on the room; rounded to whole pixels, the two could take turns between two
  sizes for good, which nudged every copy of the source (the picture itself stayed put) and kept the
  filters around it busy.

## For developers

- `tests/run-perf.sh <build dir>` measures what StageKit's filters cost a frame, headless, on a
  synthetic collection, per filter kind (see the README's *Development*).
