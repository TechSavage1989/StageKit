# StageKit 0.1.0-betaNEXT

Scene Fit and Fit to Space keep the gap from the image you see, share a column fairly, keep the size you set by hand, and never let Space priority cover another source.

## Fixed

- **A source that keeps its size next to a resized camera.** When the camera is fitted to the
  column's width and leaves room above and below its image, the source beside it (a chat box with
  *Resize to fit* unticked, say) was put at the far edge of the screen, and the camera's box grew
  to fill the room between them: the box was the gap from everything, but the camera's image
  floated inside it, and the chat box was more than the gap from it. Now the two are packed
  together towards the top: the camera's image is the gap from the edge and the chat
  box the gap from the image. It settles in one move and then stays. This needs *Align in the
  space* set to the middle on both. Scene Fit and Fit to Space alike.
- **Several resized sources in one column.** Two handheld windows and a camera view, all
  resized, shared a column; the camera's box took most of the column's height while its image used
  a third of it. Now a resized source's box is just its image wherever another resized source
  is above, below or beside it. A source that keeps its size beside it changes nothing: a 4:3
  capture next to the camera and chat column keeps the capture's whole space. Nothing moves on screen; the boxes say what each takes. A source
  whose image changes shape (a window made wider, a game changing resolution) still grows into
  its space at once.
- **"Its sources did not settle in 4 passes".** A column of three resized sources needed more
  passes than there were, after a start and after a change of mode. A Scene Fit now works its
  sources out down the list and back up it in turn, up to eight times, and settles in the same
  tick.
- **Unticking Resize to fit** brings back the size you last gave the source by hand, not the size
  it had before the filter was added. A source that never kept a size still goes back to that one.
- **A resize by hand is read once, when you let go.** It was read on every frame of the drag and
  of the dock's glide after it (*Stop resizing at edges*), and the whole column was worked out again
  each time: the log said "the size kept ... went from ... to ..." many times in a row. The source
  is left alone while you resize it and the size counts once it has stayed put for 0.3 s.
- **Takes space first never covers another source.** A source that keeps its size (*Resize to
  fit* unticked) cannot make room by shrinking, and the source taking space first went right over
  it. Now it stops the gap short of that source's size where it is kept. Sources that resize make
  room as before. Only *Overlap only when it fills* lets sources overlap.

## Good to know

- *Use visible pixels* was working: it is on as it comes, also for each source of a Scene Fit, and
  a Cropped View of a camera is measured by what it shows.
- Only sources above and below each other are packed this way. Side by side nothing changes: a
  4:3 game beside a chat column that keeps its size is placed as before, the column against the
  screen's edge and the game centred beside it. No setting changed.
- Not yet seen on Windows. The flashing back and forth seen earlier in the same scene was not
  reproduced; if it comes back, the log helps.
- A source set to *Takes space first* now moves when a source beside it that keeps its size is
  hidden or shown: it takes the room while that source is hidden and gives it back.
