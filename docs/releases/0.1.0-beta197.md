# StageKit 0.1.0-beta197

Auto Capture stays on a game while OBS picks its image up again, instead of letting go of it for seconds; Auto Frame after an Automatic Window Switcher goes by the window on screen: a browser shown after Dolphin is no longer called Dolphin and cut to its 4:3.

## Fixed

- **A game's image comes back without Auto Capture letting go.** When a game goes full-screen or
  makes its window again, or an emulator starts or stops a game, OBS loses the image for a
  moment. Auto Capture used to switch the Game Capture to *Capture any fullscreen application*
  whenever none of the game's windows could be seen, and back to the game only once one could,
  seconds or minutes later, with OBS starting the capture over each time. Now the capture stays
  aimed at the game for as long as its program runs, and OBS picks the image up again by itself.
- **Only a game you click into takes over meanwhile.** Another game on *Always capture*, or one
  remembered as a game, that is open behind waits. A program that closes is waited for about
  three seconds, in case it is only making its window again; then another game that is open
  takes over, and with none the capture goes back to *Capture any fullscreen application* as
  before. A program that opens again is followed within a quarter of a second.
- **A game's new window is followed at once.** When its window is made again as another kind of
  window, the capture is aimed at it straight away while there is no image, and left as it is
  while the image is there, since aiming it again would make OBS start over.
- **An emulator's minimised menu is not taken for its game.** When an emulator's game window
  closes while its menu window is minimised, the capture lets go within about half a second and
  is aimed at nothing, as with the menu open (it went to *Capture any fullscreen application*
  before), and the menu is not aimed at when it is brought back. A game whose window is only
  hidden while it makes its drawing again, or that OBS hooks again at once, is kept.
- **Switching Auto Capture on again hands the capture back.** After the capture was aimed by
  hand (the *Capture Active Window* key), switching Auto Capture on again left it where it was
  while Auto Capture's game from before was still open. Now it is aimed afresh at once.
- **OBS's log says when the aim is kept.** `kept on <program> while its picture comes back`, once
  each time the image goes, and once more when none of the program's windows can be seen.

- **Auto Frame names the window the switcher shows.** On a Window Capture with an Automatic
  Window Switcher, Auto Frame's top line said *Capturing Dolphin.exe. Aspect ratio: 4:3, from your
  saved shapes* while a web browser was on screen, and the browser was cut to 4:3. Since beta119
  the switcher draws a capture it keeps ready for the window shown and leaves the Window Capture
  itself aimed at an earlier window, and Auto Frame read the program from there. It now asks the
  switcher: the top line names the program of the window on screen, and that program's saved
  shape is the one used, by file name or by part of the window's title (a browser's title that
  changes with its tab is followed). Going back to Dolphin brings its 4:3 back.
- **A switch to another program is a new program for Auto Frame.** The shape it starts from, the
  shapes it learns and the shape it holds go by the program shown, and it looks again the moment
  the switcher changes window, before the next image is drawn, even when the two windows are the
  same size. When the window shown closes, its shape stays on its last image for the moment that
  image is held; once the switcher shows nothing, Auto Frame names no program.
- **Switched off and on again, the switcher says what it shows.** It works out afresh which window
  to show, as when OBS starts, instead of naming the window it showed before while the Window
  Capture's own window was drawn (and Auto Frame cutting that one to the other's shape).
- **Auto Frame's *Program or window* list** offers the program on screen first.

## Good to know

- OBS's own hooking still takes its time: some games, Vulkan games and emulators in particular,
  take a few seconds to show, and an emulator's menu cannot be hooked. The Game Capture's own
  *Hook Rate* sets how often OBS tries; see Troubleshooting in the README.
- A program remembered as a game that gives no image is still left alone after ten seconds, and
  a game whose window closes while its program shows another (Dolphin back in its menu) is still
  let go of.
- Not yet tried on Windows.

- With the switcher switched off, or before it has shown any window, Auto Frame goes by the Window
  Capture's own window, as before.
- Not yet tried on Windows.
