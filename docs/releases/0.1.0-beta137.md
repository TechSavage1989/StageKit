# StageKit 0.1.0-beta137

One hundred and thirty-seventh pre-release: Auto Capture finds a game sooner in an emulator that was
already open, and the dock's order tools are a block with four drawings
that cannot be mistaken for one another. It passes the automated tests on Linux; the Windows side
has not run in a real OBS here.

## Changed

- **The order tools are stacked two by two** on the StageKit dock's Arrange tab, the size of the
  line-up tools above them: *To the front* and *Forward one* on top, *To the back* and *Back one*
  under them.
- **Each has its own drawing.** All four used to show two overlapping sheets and looked alike.
  Now: *To the front* is an arrow up to a heavy line at the top, *To the back* an arrow down to one
  at the bottom. *Forward one* is a sheet with an arrow rising from it, and *Back one* a sheet with
  an arrow dropping from it. The names are still in the tooltips.

## Fixed

- **Auto Capture was slow to pick up a game in an emulator that had been open for a while.** A
  program that gives the capture no image is left alone and tried again later. Those later tries
  lasted only 5 seconds and came 30 seconds, then 1, 2 and up to 5 minutes apart. Your log showed
  Ryujinx needing about 7 seconds to give its first image, so three tries in a row came to
  nothing. Each try now lasts the full 10 seconds, the waits are 20 seconds growing to one minute
  at most, and a program is tried again at once when you click back into it.
- **The filter says when it is aimed but has no image yet**: *Aimed at Ryujinx.exe, which shows no
  image yet. A game running in it is captured as soon as it draws.* Before, it said *Now
  capturing* over an empty capture.

A program on *Always capture* was and is tried all the time, with no waits.
