# StageKit 0.1.0-beta113

One hundred and thirteenth pre-release: a capture that starts up as its scene is switched to no
longer stays missing for the whole Morph transition. It passes the automated tests on Linux.

## Fixed

- **Morph: a display capture came in only when the transition was over.** OBS stops a display
  capture while no scene on screen shows it and starts it again when its scene is switched to,
  which takes a moment. Morph worked out where each item goes once, at the very start, when the
  capture had not started yet and so had no size. An item set to fit a bounding box then had no place at all, was left out for the whole change, and appeared at a
  stroke at the end. Morph now works an item's place out again whenever its source changes size,
  so the capture fades in with the rest from the moment it has a picture. The same went for
  anything else in a bounding box that starts or changes size during the change.

## Good to know

- The capture itself still needs a moment to start (that is Windows and OBS, not StageKit), so it
  joins the fade a little after the start. If that moment can still be seen, OBS's log now says
  how long it was: a line starting `Morph:` and ending `had no picture for the first ... ms of the
  change`.
- This could not be tried with a real display capture here (Linux has none); the test uses a
  stand-in that starts part-way through the change.
